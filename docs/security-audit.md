# Security audit (mark-only)

[← Back to README](../README.md)

The proxy sits inside every agent loop: it sees the prompt a client sent, the tool results that came back, and what the model answered and asked to run. The audit judges that traffic **after the turn has been served** and records what it found — it never blocks, holds or rewrites a reply, and the serving path never waits on a verdict. (Mark first, act later: what a flag can safely do once humans trust it is a separate decision.)

Five flag kinds, each shown as a red **confirmed** or amber **watch** badge: `injection` (text trying to hijack the model), `exfil` (data leaving — transfers with payloads, cloud-metadata probes, credential reads), `recon` (machine inventory — deliberately a watch by default: dev agents do this legitimately all day; a chain of probes or a probe next to a transfer confirms it), `privesc` (sandbox-boundary pushes: `unshare`, tmpfs mounts, setuid), `harm` (the guard's own content categories). Chains matter more than single lines: an inventory in a tool result plus an upload to an object store in the reply is one story.

Three detectors, cheapest first — all three judge the **same reconstruction**: a streamed reply's tool calls are rebuilt from its SSE fragments and their `command` unescaped, so the detectors read `curl -X PUT --data-binary @…` and not the `curl  - X  PUT` the argument deltas spell on the wire, and the whole stored response is judged with its **tail** kept (a streamed call sits at the end), not its first 128 KiB.

- **Rule scanner** (free, no network, on by default) — boundary-aware regex rules over what is new in the turn, each one labelled so a badge says what it actually saw: cloud-metadata endpoints (`169.254.169.254`, `metadata.google.internal`, …), a watch-host list (`*.aliyuncs.com`, `webhook.site`, … plus your `extra_watch_hosts`), transfer-with-payload shapes, credential paths, inventory commands, sandbox commands, classic instruction-override phrases, and secrets arriving in a tool result — a key shape (PEM, `AKIA…`, `ghp_…`, `sk-…`, `xox[bp]-`), a `PASSWORD=<real value>` assignment, or a whole dotenv **body** — three-plus `NAME=value` lines **and** one line whose name says secret (`*_PASSWORD`, `*_TOKEN`, `*_KEY`, `passwd`…) holding a real value: a credential file is judged by its shape *plus* its names, because the shape alone is a Makefile, a PKGBUILD header or a `printenv`. Boundaries are the other half of the story: `.env` no longer matches `process.env`, `| sh` no longer matches `outText || showStderr`, `ip addr` no longer matches a description of a zip address — those were this host's own false positives, and two of them together used to escalate to a red exfil.
- **`d3-nano` noul intent questions** on the audit backend (`/v1/systemone`): does this text ask an assistant to override its instructions (that verdict is `injection`), disclose a secret, or send data to a third party (both `exfil`). One bounded batch per turn, and only about something that can answer them: a tool result that is code or command output — or under 40 characters — is never asked, because code says yes to those questions far too readily; fetched pages and documents are where indirect injection lives, and that is what gets the NPU.
- **`qwen3guard-gen` moderation** (`/v1/moderations`) on this turn's new user messages and the **prose** of the reply — its tool calls are stripped before the guard is asked, because a shell command is the rule scanner's business, not a topic of conversation; the guard's `Jailbreak` lands as `injection`, its other categories as `harm`.

**Where something is judged matters as much as the pattern.** The exfil transfer, credential-path and privesc rules read the model's **own reply** — its prose and the tool calls it issued — because a user or a document naming `docker/.env` is describing a file, not shipping it, and a chain now needs its transfer leg to be the reply's, so two prose matches can no longer confirm an exfil between them. **A watch host counts as a destination only where the model met it** — in its own reply (the address it was told to ship to) or in a tool result that carried it back — so naming `webhook.site` in your own message is an amber watch and nothing more; it used to confirm a red exfil on its own, which is how ordinary traffic about a test listener got flagged. A secret is the opposite half: `secret-in-tool-output` judges **tool results** and, on its own, only watches — reading a config is not leaving — the pair that confirms is a secret in a result and a transfer in the same reply.

Configure with `settings.audit` (`enabled: off | scanner | full` — `scanner` is the default): the model layer is opt-in because it copies judged text to the audit backend and spends its NPU, so that traffic is bounded (default: 2 in flight, queue 64 — past it turns are dropped and counted, never waited on) and a backend that stops answering degrades the audit to scanner-only until it replies. Memory rides the same two knobs, but a job is not one buffer: it pins its reply (bounded by `log_content_limit`) **and** the request body it came with (bounded by `max_body_bytes`), so the worst case is on the order of `(queue + concurrency) × (log_content_limit + body)` — roughly 66 MiB of replies at the shipped defaults plus whatever the bodies queued at that moment weigh — and a redacted turn holds one more reply-sized buffer while it streams. A **model** verdict is red **confirmed** at `flag_threshold` (default 0.85) and is not recorded at all below `watch_floor` (default **0.6**) — a shrug is not a finding — with `tool_watch_floor` (default **0.75**) as the stricter bar for a verdict about a tool result, where those intent questions are least reliable. **Most rule hits are watches, not confirmations**: only `metadata-ip` and `injection-phrase` confirm alone; a transfer, a credential path, an inventory probe, a sandbox push or a secret in a result goes red only when a chain in the same turn makes it a story — a transfer plus a watch host **the reply or a tool result named**, a transfer plus a credential path, several inventory probes (or one beside the reply's own transfer), several boundary pushes, a secret in a tool result plus a reply transfer. `guard_strict` (default **true**) asks the moderation model for its *controversial* band on top of its unsafe one: noisier, and the only thing that catches an agent being steered — on a **reply** that band is kept only at or above `flag_threshold` (a dev agent's own prose trips it all day), while a person's own words keep the whole band, and a verdict the guard itself flagged is never dropped. `X-Redact-Log` traffic is judged in memory by default: verdicts are stored, its text never is.

Every **new** user message in a turn is judged — not just the last one, which is how a harness that appends its own boilerplate after the real instruction used to get the real instruction ignored and the boilerplate flagged forever — and each block is judged **once per conversation**: the audit keeps a bounded (~4 096 blocks), in-memory ledger of *keyed digests* of the user blocks it has already run, so a re-sent block costs no rule hit and no NPU question. The contract that comes with it: a digest is content-derived metadata about traffic that may be redacted, so it lives in this process only and is written nowhere — not the request log, not `/metrics`, not the UI — and a restart forgets it; a block forgotten mid-conversation is judged again, which raises a duplicate flag, and that is the accepted cost.

The gaps, said here rather than found later: a user who pastes an exfil command and has the model run it **verbatim** is outside the reply-scoped rules (the reply only repeats what it was given), and so is one who only **names** a watch host — pasting a `webhook.site` URL and asking nothing else is an amber watch now, because a red exfil always means a transfer the model itself asked for — and the transfer patterns are a set, not a parser, so an asked-for upload written in a shape they do not read (plain `curl -T <file> <url>`, where `--upload-file` is matched and `-T` is only matched as `-t http…`) is two amber watches rather than a red one; chains are still **single-turn**, so reading `.env` in turn N and `curl`-ing in turn N+1 will not confirm; **commands are the rule scanner's domain alone** — now that the reconstruction makes them legible we still keep them from the moderation guard deliberately, which is a split of duties, not an oversight; a dumped credential file is judged by shape **and** a secret-shaped name, so an `env` dump that does hold a `*_TOKEN=` or `*_PASSWORD=` line goes amber (accepted: that output is credential material) and one whose every name is innocent — a file of `SIGNIN=password` and friends — stays quiet; and a **redacted** turn keeps its verdicts and the pattern label that fired, never its text. For a second opinion on real traffic, `cargo run --example audit_replay -- /srv/logs/ollamamq-requests.jsonl` runs this same scanner over a recorded request log offline — the example documents its own limit: a log written before the tail was kept has already lost the end of long replies, so replaying one proves the false-positive side, not the streamed-call fix.

Flags appear as `⚑` badges on log rows, Activity lines and conversation headers, with a verdict block (who said so, on what, with what confidence, the matched excerpt where text is stored) inside each flagged turn; the Logs page has a **Flagged** filter, Settings shows mode, queue depth, drops and backend state, and `/metrics` counts scans, flags by kind, drops and backend-down seconds. A verdict arrives seconds after its turn is served — a row gaining a badge while the page sits open is the point, not a bug.
